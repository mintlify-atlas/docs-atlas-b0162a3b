Membrane supports Postgres as an alternative to SQLite, enabling concurrent writes and vector-based retrieval.

## Prerequisites

- Postgres 16 or later
- (Optional) pgvector extension for embedding-based retrieval

---

## Quick Start with Docker

<Steps>
  <Step title="Start Postgres with pgvector">
    ```bash
    docker run -d \
      --name membrane-postgres \
      -e POSTGRES_DB=membrane_test \
      -e POSTGRES_USER=membrane \
      -e POSTGRES_PASSWORD=membrane \
      -p 5432:5432 \
      pgvector/pgvector:pg16
    ```
  </Step>

  <Step title="Verify the connection">
    ```bash
    psql "postgres://membrane:membrane@localhost:5432/membrane_test?sslmode=disable" -c "SELECT version();"
    ```
  </Step>

  <Step title="Start Membrane">
    ```bash
    ./bin/membraned --postgres-dsn "postgres://membrane:membrane@localhost:5432/membrane_test?sslmode=disable"
    ```
  </Step>
</Steps>

## Connection Strings

Membrane uses the `pgx` driver and accepts standard Postgres DSN formats.

### Basic DSN

```bash
postgres://username:password@host:port/database
```

### With Query Parameters

```bash
postgres://membrane:membrane@localhost:5432/membrane?sslmode=require&pool_max_conns=20
```

### Common Parameters

| Parameter | Description | Default |
|-----------|-------------|--------|
| `sslmode` | TLS mode: `disable`, `require`, `verify-ca`, `verify-full` | `prefer` |
| `connect_timeout` | Connection timeout in seconds | `5` |
| `application_name` | Application name for `pg_stat_activity` | `pgx` |
| `pool_max_conns` | Maximum connection pool size | `4` |

<Warning>
In production, always use `sslmode=require` or higher. The examples use `sslmode=disable` for local development only.
</Warning>

### Environment Variable

Set the DSN via environment variable to avoid hardcoding credentials:

```bash
export MEMBRANE_POSTGRES_DSN="postgres://membrane:password@db.example.com:5432/membrane?sslmode=require"
./bin/membraned
```

Or in your config file:

```yaml config.yaml
backend: postgres
# postgres_dsn: ""  # reads from MEMBRANE_POSTGRES_DSN
```

## Schema Initialization

Membrane automatically creates the required schema on first connection.

### Automatic Setup

The `Open` function in `pkg/storage/postgres/postgres.go` executes the embedded `schema.sql` DDL:

```sql
CREATE EXTENSION IF NOT EXISTS vector;

CREATE TABLE IF NOT EXISTS memory_records (
    id TEXT PRIMARY KEY,
    type TEXT NOT NULL CHECK(type IN ('episodic','working','semantic','competence','plan_graph')),
    sensitivity TEXT NOT NULL CHECK(sensitivity IN ('public','low','medium','high','hyper')),
    confidence REAL NOT NULL CHECK(confidence >= 0 AND confidence <= 1),
    salience REAL NOT NULL CHECK(salience >= 0),
    scope TEXT,
    created_at TIMESTAMPTZ NOT NULL,
    updated_at TIMESTAMPTZ NOT NULL
);

CREATE TABLE IF NOT EXISTS decay_profiles (
    record_id TEXT PRIMARY KEY REFERENCES memory_records(id) ON DELETE CASCADE,
    curve TEXT NOT NULL CHECK(curve IN ('exponential')),
    half_life_seconds BIGINT NOT NULL CHECK(half_life_seconds > 0),
    min_salience REAL NOT NULL DEFAULT 0,
    reinforcement_gain REAL NOT NULL DEFAULT 0.1,
    last_reinforced_at TIMESTAMPTZ NOT NULL,
    pinned BOOLEAN NOT NULL DEFAULT FALSE,
    deletion_policy TEXT NOT NULL DEFAULT 'auto_prune'
);

CREATE TABLE IF NOT EXISTS payloads (
    record_id TEXT PRIMARY KEY REFERENCES memory_records(id) ON DELETE CASCADE,
    payload_json JSONB NOT NULL
);

-- Additional tables: tags, provenance_sources, relations, audit_log, competence_stats
```

### Manual Schema Creation

If you need to inspect or run the schema manually:

<Steps>
  <Step title="Extract the schema SQL">
    The schema is embedded in the binary. To view it, check:
    ```bash
    cat workspace/source/pkg/storage/postgres/schema.sql
    ```
  </Step>

  <Step title="Run it manually">
    ```bash
    psql "postgres://membrane:membrane@localhost:5432/membrane" < schema.sql
    ```
  </Step>
</Steps>

<Note>
The schema uses `CREATE TABLE IF NOT EXISTS` and `CREATE EXTENSION IF NOT EXISTS`, so re-running it is safe (idempotent).
</Note>

## pgvector Extension

The pgvector extension is required for Tier 3 and Tier 4 deployments.

### Installation

<CodeGroup>
```bash Docker (Recommended)
docker run -d pgvector/pgvector:pg16
```

```bash Ubuntu/Debian
sudo apt-get install postgresql-16-pgvector
```

```bash macOS (Homebrew)
brew install pgvector
```

```bash From Source
git clone https://github.com/pgvector/pgvector.git
cd pgvector
make
make install  # requires pg_config in PATH
```
</CodeGroup>

### Verification

```sql
CREATE EXTENSION IF NOT EXISTS vector;
SELECT * FROM pg_extension WHERE extname = 'vector';
```

Expected output:
```
 extname | extversion
---------+------------
 vector  | 0.7.0
```

### Embedding Dimensions

Membrane creates a `trigger_embeddings` table with a configurable vector dimension:

```sql
CREATE TABLE IF NOT EXISTS trigger_embeddings (
    record_id TEXT PRIMARY KEY REFERENCES memory_records(id) ON DELETE CASCADE,
    embedding vector({{EMBEDDING_DIMENSIONS}}),
    model TEXT NOT NULL,
    created_at TIMESTAMPTZ NOT NULL
);
```

The `{{EMBEDDING_DIMENSIONS}}` placeholder is replaced at runtime based on your config:

```yaml config.yaml
embedding_dimensions: 1536  # default for text-embedding-3-small
```

<Warning>
If you change `embedding_dimensions` after data exists, you'll get a dimension mismatch error. To migrate, you must re-embed all records or use a different table.
</Warning>

### Embedding Metadata Validation

Membrane stores embedding configuration in the `embedding_metadata` table:

```sql
CREATE TABLE IF NOT EXISTS embedding_metadata (
    key TEXT PRIMARY KEY,
    value TEXT NOT NULL
);
```

On startup, it verifies that `dimensions` and `model` match the configuration. If there's a mismatch:

```
embedding metadata mismatch for dimensions: configured "1536", stored "768"
```

This prevents accidental use of incompatible embeddings.

## Indexes

Membrane creates indexes optimized for memory retrieval queries.

### Standard Indexes

```sql
CREATE INDEX IF NOT EXISTS idx_records_type ON memory_records(type);
CREATE INDEX IF NOT EXISTS idx_records_salience ON memory_records(salience DESC);
CREATE INDEX IF NOT EXISTS idx_records_type_salience ON memory_records(type, salience DESC);
CREATE INDEX IF NOT EXISTS idx_records_scope_sensitivity ON memory_records(scope, sensitivity);
CREATE INDEX IF NOT EXISTS idx_tags_tag ON tags(tag);
```

### Vector Index (pgvector)

```sql
CREATE INDEX IF NOT EXISTS idx_trigger_embeddings_ann
    ON trigger_embeddings USING ivfflat (embedding vector_cosine_ops)
    WITH (lists = 100);
```

**IVFFlat parameters:**

- `lists = 100`: Number of inverted lists (adjust based on dataset size)
- `vector_cosine_ops`: Cosine distance operator class

For large datasets (>1M embeddings), consider increasing `lists` or using HNSW:

```sql
CREATE INDEX idx_trigger_embeddings_hnsw
    ON trigger_embeddings USING hnsw (embedding vector_cosine_ops)
    WITH (m = 16, ef_construction = 64);
```

<Note>
Membrane uses the IVFFlat index by default. HNSW is faster for large datasets but requires more memory.
</Note>

## Connection Pooling

The `pgx` driver uses connection pooling by default.

### Default Pool Settings

```go
// From pgx documentation
MaxConns:          4
MinConns:          0
MaxConnLifetime:   1 hour
MaxConnIdleTime:   30 minutes
HealthCheckPeriod: 1 minute
```

### Custom Pool Configuration

Pass pool parameters via DSN:

```bash
postgres://membrane:membrane@localhost:5432/membrane?pool_max_conns=20&pool_min_conns=5
```

Or use a connection pool URL:

```bash
postgres://membrane:membrane@localhost:5432/membrane?pool_max_conns=20&pool_max_conn_lifetime=30m
```

### Monitoring Pool Usage

Query active connections:

```sql
SELECT 
    application_name,
    state,
    COUNT(*)
FROM pg_stat_activity
WHERE datname = 'membrane'
GROUP BY application_name, state;
```

## Migration from SQLite

There is no automated migration tool yet. Manual migration steps:

<Steps>
  <Step title="Export SQLite data">
    Use a custom script to read all records from SQLite:
    ```go
    sqliteStore, _ := sqlite.Open("membrane.db", "")
    records, _ := sqliteStore.List(ctx, storage.ListOptions{})
    ```
  </Step>

  <Step title="Create Postgres schema">
    Start Membrane with Postgres DSN to auto-create schema:
    ```bash
    ./bin/membraned --postgres-dsn "postgres://..." &
    sleep 2
    pkill membraned
    ```
  </Step>

  <Step title="Import records">
    ```go
    pgStore, _ := postgres.Open("postgres://...", postgres.EmbeddingConfig{})
    for _, rec := range records {
        pgStore.Create(ctx, rec)
    }
    ```
  </Step>
</Steps>

<Warning>
Ensure record IDs are preserved during migration to maintain relations and audit trails.
</Warning>

## Production Checklist

<Steps>
  <Step title="Enable TLS">
    Use `sslmode=require` or `sslmode=verify-full` in the DSN.
  </Step>

  <Step title="Use strong credentials">
    Set a unique password for the `membrane` user.
    ```sql
    ALTER USER membrane WITH PASSWORD 'strong-random-password';
    ```
  </Step>

  <Step title="Configure connection pooling">
    Set `pool_max_conns` based on expected concurrency (default: 4).
  </Step>

  <Step title="Enable backups">
    Use `pg_dump` or continuous archiving (WAL-E, pgBackRest).
    ```bash
    pg_dump -Fc membrane > membrane-$(date +%Y%m%d).dump
    ```
  </Step>

  <Step title="Monitor query performance">
    Enable `pg_stat_statements`:
    ```sql
    CREATE EXTENSION pg_stat_statements;
    ```
  </Step>

  <Step title="Tune shared_buffers and work_mem">
    Adjust Postgres config based on available memory:
    ```ini postgresql.conf
    shared_buffers = 256MB       # 25% of system RAM
    work_mem = 16MB              # per-sort buffer
    maintenance_work_mem = 128MB # for index builds
    ```
  </Step>
</Steps>

## Troubleshooting

### "pq: password authentication failed"

Check credentials and DSN format:

```bash
psql "postgres://membrane:membrane@localhost:5432/membrane" -c "SELECT 1;"
```

### "pq: database \"membrane\" does not exist"

Create the database first:

```bash
createdb -U postgres membrane
```

Or via SQL:

```sql
CREATE DATABASE membrane OWNER membrane;
```

### "extension \"vector\" does not exist"

Install pgvector (see [pgvector Extension](#pgvector-extension)).

### "embedding metadata mismatch"

You changed `embedding_dimensions` after data was created. Options:

1. Reset the database: `TRUNCATE trigger_embeddings, embedding_metadata;`
2. Use a new database with the new dimensions
3. Migrate embeddings (requires custom script)

### Slow vector queries

Rebuild the IVFFlat index or switch to HNSW:

```sql
DROP INDEX idx_trigger_embeddings_ann;
CREATE INDEX idx_trigger_embeddings_hnsw
    ON trigger_embeddings USING hnsw (embedding vector_cosine_ops);
```
